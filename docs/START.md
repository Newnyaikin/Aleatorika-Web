# Публикация Алеаторики: пошагово

## 1. Подготовьте компьютер

1. Создайте аккаунт на https://github.com, подтвердите email.
2. Установите Git: https://git-scm.com/downloads.
3. Установите VS Code: https://code.visualstudio.com/.
4. После установки Git перезапустите VS Code.
5. Распакуйте нужный ZIP в обычную папку. Не работайте внутри ZIP.
6. В VS Code откройте **File → Open Folder** и выберите именно корень одного проекта. Не открывайте общую папку, содержащую сразу Android и Web.

Откройте **Terminal → New Terminal**. Проверьте:

```bash
git --version
```

Первый раз задайте имя автора и email. Замените значения своими, не копируйте примеры как реальные данные:

```bash
git config --global user.name "Ваше имя"
git config --global user.email "Ваш email для коммитов"
```

Email становится частью истории коммитов. Если не хотите показывать личную почту, возьмите свой точный адрес `noreply` из GitHub → Settings → Emails. Его нельзя угадывать.

## 2. Опубликуйте папку из VS Code

Отдельно выполните эти действия для Android, затем для Web:

1. Откройте **Source Control** (`Ctrl+Shift+G`).
2. Нажмите **Initialize Repository**. Если репозиторий уже инициализирован, этот шаг пропустите.
3. Просмотрите список файлов. Папка `.github/` обязательно должна присутствовать. В Android также нужны `android/` и `shared/`. Приватных ключей, паролей, `local.properties` и папок сборки в списке быть не должно.
4. Нажмите **Stage All Changes** — значок `+` рядом с Changes.
5. Введите сообщение `Initial project` и нажмите **Commit**.
6. В терминале выполните команду для имени основной ветки:

```bash
git branch -M main
```

7. Нажмите **Publish Branch / Publish to GitHub**. Также команда доступна через `Ctrl+Shift+P → Publish to GitHub`.
8. Разрешите вход в GitHub в открывшемся браузере и вернитесь в VS Code. Пароль или токен не нужно записывать в файлы проекта.
9. Выберите имя нового репозитория, указанное ниже, и **Public repository**. Для общедоступных исходников/сайта это самый простой вариант; GitHub Pages в приватных репозиториях зависит от плана.
10. Откройте созданный репозиторий на GitHub. В корне должны быть файлы проекта, а не один ZIP и не лишняя внешняя папка.

Если вы заранее создали пустой репозиторий на сайте, вместо Publish подключите его как remote, заменив адрес своим:

```bash
git remote add origin https://github.com/YOUR_LOGIN/YOUR_REPOSITORY.git
git push -u origin main
```

Не выполняйте `remote add`, если `origin` уже есть. Проверить можно командой `git remote -v`. Не используйте принудительную перезапись `push --force`.

## 3. Как отправлять дальнейшие изменения

Измените файлы, сохраните их. В Source Control выполните **Stage All Changes → Commit → Sync Changes**. В сообщении коммита кратко опишите изменение. Если появилась кнопка Pull, сначала получите изменения с GitHub и разрешите конфликты, а не перезаписывайте историю.

Android и Web теперь независимы. Изменение в одной папке НЕ переносится автоматически в другую. Если исправляете общую музыкальную логику или правила, обновляйте соответствующие реализации в обоих репозиториях.

## Web: публикация отдельного сайта

Рекомендуемое имя репозитория: **aleatorika-web**.

В корне должны лежать:

```text
index.html
manifest.webmanifest
sw.js
*.js и *.css
fonts/
.github/workflows/pages.yml
.github/workflows/release.yml
tools/
docs/
README.md
```

Не переносите `index.html` в дополнительную папку `web/`: этот подготовленный репозиторий уже устроен иначе, чем прежний общий проект.

### Включите GitHub Pages один раз

1. Откройте **aleatorika-web** на GitHub.
2. **Settings → Pages**.
3. В разделе **Build and deployment**, поле **Source**, выберите **GitHub Actions** — не Deploy from a branch.
4. Не создавайте новый шаблон workflow: в проекте уже есть нужный файл.
5. Перейдите в **Actions → Web - check and publish site**.
6. Нажмите **Run workflow → main → Run workflow**.
7. Дождитесь зелёных заданий **build** и **deploy**.
8. Откройте ссылку у задания deploy или Environment **github-pages**. Она обычно выглядит так:

```text
https://YOUR_LOGIN.github.io/aleatorika-web/
```

Подставьте свой логин GitHub. Если имя репозитория другое, изменится последняя часть URL. Точный адрес показывает успешный deploy. HTTPS важен для микрофона.

Если самый первый автоматический запуск был красным, потому что Pages ещё не включили, после выбора Source просто запустите workflow заново.

### Как обновлять сайт

В Web-проекте сохраните изменения, затем **Stage → Commit → Sync Changes**. Каждая отправка в `main` автоматически проверяет и публикует сайт. Никакой ручной загрузки ZIP на хостинг не нужно. Pull request проверяет файлы, но не меняет публичный сайт.

Если сайт выглядит старым, закройте все его вкладки и установленный PWA, затем откройте заново. Старую открытую страницу может обслуживать прежний service worker. Микрофон всё равно требует разрешения браузера и ОС.

### Отдельный Web Release с ZIP

Это необязательный шаг: сайт уже работает через Pages. Если хотите также ссылку на скачивание веб-версии, выполните из корня Web-проекта:

```bash
git tag v1.0.0
git push origin v1.0.0
```

Запустится **Web - release ZIP**. В Releases появятся:

- `Aleatorika-1.0-web.zip` — готовый статический сайт, index.html внутри ZIP лежит в корне.
- `Aleatorika-Web-source.zip` — исходники с инструкциями и workflow.

У Android и Web разные репозитории, поэтому тег `v1.0.0` может существовать в каждом независимо. Создание Web-тега само по себе не публикует незагруженные изменения на сайте: сначала отправьте коммит в `main`.

### Если сайт не публикуется

- Проверьте, что `pages.yml` находится именно в `.github/workflows/` и ветка называется `main`.
- Settings → Pages → Source должно быть **GitHub Actions**.
- Если Actions выключены политикой организации, понадобится разрешение администратора.
- `404`: сначала дождитесь успешного deploy, затем открывайте URL с именем репозитория в конце.
- Проверьте Actions → deploy: при ограничениях Environment github-pages разрешите развёртывание из `main` согласно вашей политике.
- В архиве/репозитории не должно быть ещё одной внешней папки вокруг index.html.
